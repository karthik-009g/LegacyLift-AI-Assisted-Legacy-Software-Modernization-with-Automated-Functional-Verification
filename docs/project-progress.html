Why evaluation takes longer than building

Reference behavior is subtle. Permissions, default fields, status transitions, response headers, and audit journals must match Rails behavior.
Unseen scenarios expose gaps. A candidate can pass examples used during development and still fail held-out cases. Those failures cannot be fed back into that same trial.
AI changes are experiments. Each prompt, evidence, and bounded repair needs its own recorded run. Model output can regress another case or exceed the safe edit window.
Docker adds independent execution. Both implementations must run under the same isolated conditions, then compare HTTP responses and database effects.
Review and release need evidence. Passing code must be source-reviewed, approved, exported, replayed, and reproducible from a fresh snapshot.
Test counts validate the platform. The 456 tests show the harness is healthy. They do not mean all three AI-generated migrations pass.
