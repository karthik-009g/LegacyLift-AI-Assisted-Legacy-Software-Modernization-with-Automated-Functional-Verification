## Approved scope

Modernize selected workflows from Redmine 4.2.10 (Ruby/Rails) into a maintained Python/FastAPI service, with independent functional verification. The first units are issue creation, visibility-aware retrieval, and status updates including relevant audit effects. Preserve the original database schema initially and operate only on synthetic fixture copies.

The existing Flask/FastAPI prototype and its recorded negative model experiment remain a regression fixture. Its completion audit does not describe completion of v2.

## Execution decisions

- Legacy source: `https://github.com/redmine/redmine`, tag `4.2.10`, resolved commit `9118c6dcb4ffe203f7029eb89523cd8a56b85cde`.
- Reference image: `redmine:4.2.10@sha256:d26185b803ec88617d101a041c3614c136385011fd0d7b2c6acb8cacb58e6e1e`.
- Redmine source has GPL notices. Keep attribution and upstream source separate; do not label source-derived output permissively licensed by default.
- Legacy and candidate application code never runs in the API process. No provider credentials, production data, host-wide mounts or Docker socket enter application containers.
- External request/response observations and fixture database changes are authoritative. Candidate-reported session state alone cannot establish equivalence.
- Hidden expected results are kept outside candidate images. Generation/repair sees development evidence only; final held-out results do not feed that trial's repair loop.
- Automatic changes affect an isolated workspace; originals stay immutable. Cleanup supports migration rather than broad repository refactoring.
- Generation uses hosted free-plan providers. The default tries Groq then Gemini; benchmark runs fix a provider and pause on quota exhaustion.
- Initial study: three workflows, ten scenarios per workflow (six guidance/four held out), three conditions and three trials: 27 initial trials, at most 81 migration calls including follow-ups.
- Compatibility mismatches, approved security deviations and infrastructure failures are reported separately. Security scanners do not certify an application secure.
- Work remains local. No GitHub pushes, workflow dispatches or public deployment occur during implementation.
